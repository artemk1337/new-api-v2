# UI Local Review

Проверяй пользовательский сценарий в настоящем локальном приложении, а не только по коду.

## Подготовка

1. Проверь `git status`, `bun --version` и `docker info`.
2. Если Bun отсутствует, сначала получи разрешение; устанавливай его только во временную директорию, не в репозиторий.
3. Быстрый запуск:

```bash
cd web && bun install --frozen-lockfile
docker compose -f docker-compose.dev.yml up -d --build
cd web/default && bun run dev -- --host 0.0.0.0 --port 5173
```

Открой `http://127.0.0.1:5173/`. Дождись доступности backend: не считай временный 504 успешной проверкой.

## Проверка в браузере

1. Открой целевой сценарий в Browser и проверь DOM, видимые ошибки и console.
2. Сделай скриншот до и после целевого действия; сохраняй его в `/private/tmp`, а не в репозиторий.
3. Повтори ключевой сценарий в mobile viewport шириной `390px`.
4. Проверь управление с клавиатуры: фокус, `Enter`/`Space` для интерактивных элементов и `Escape`.
5. Для popover внутри drawer `Escape` должен закрывать только popover, не весь drawer.

## Завершение

1. Выполни `bun run build`, `git diff --check` и точечную проверку форматирования изменённых файлов. Отдельно сообщай о существующих, не связанных с изменением сбоях.
2. Проверь `web/default/src/routeTree.gen.ts`: dev-сервер может обновить его; не коммить generator noise, если он не относится к задаче.
3. Останови окружение после проверки:

```bash
docker compose -f docker-compose.dev.yml down
```

Не используй `down -v` без явной просьбы: volumes с локальными данными должны сохраниться.
